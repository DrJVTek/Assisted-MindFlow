## Gotchas
- GraphExecutor.execute/stream_execute are NOT called by the Orchestrator — Orchestrator only calls self._executor.topological_sort (orchestrator.py lines 394 and 428) and reimplements the execute/stream loops itself. This is exactly why the cache is dead under OPTION-KILL and why OPTION-WIRE has to re-route the Orchestrator through GraphExecutor.
- There are FOUR test files that touch GraphExecutor, not two: besides test_dirty_clean.py and test_graph_executor.py, the methods execute/stream_execute/set_node_executor are ALSO driven by tests/backend/unit/test_executor.py (lines 46-50, 95-100, 156-159, 187, 196) and tests/backend/integration/test_execution_pipeline.py (lines 42-44, 56-99). OPTION-KILL MUST update both or the green baseline breaks. The card author specifically called out only the first two; do not stop there.
- tests/backend/unit/test_orchestrator.py lines 305-362 call orchestrator.stream_execute — that is the Orchestrator's OWN method, NOT GraphExecutor.stream_execute. It is unaffected by OPTION-KILL and must keep passing. Do not confuse the two stream_execute methods.
- The mark-dirty endpoint (execution.py 171-209) is theatre today: it builds a fresh GraphExecutor (line 202), clears its dirty set (line 204), computes a dirty list and returns it — but that executor is discarded and the next execution builds another new one, so it changes nothing. Either remove it (OPTION-KILL) or make it hit the persisted executor (OPTION-WIRE).
- OPTION-WIRE closure trap: when registering per-node executors in a loop (set_node_executor(node_id, lambda: self._execute_node(node_id))), the lambda captures node_id by reference and every closure ends up using the last loop value. Use a default argument (lambda nid=node_id: ...) or a factory function.
- OPTION-WIRE streaming loss: GraphExecutor.stream_execute has no token-level streaming for the terminal node, whereas Orchestrator.stream_execute does (orchestrator.py 468-506 + _stream_terminal_node_events 508-578). A naive delegation to GraphExecutor.stream_execute will silently drop token streaming — a real regression. Preserving streaming alongside the cache is the genuinely hard part of OPTION-WIRE.
- Caching outputs across requests (OPTION-WIRE) is a correctness hazard: if a node's inputs/content change but it is not marked dirty, the user gets a stale cached result with no error — which violates the project's NO-FALLBACK / no-silent-substitution rule. The invalidation policy (W0) must be designed deliberately, not defaulted.
